# Telegram-бот «Цифровая очередь деканата» — инструкция

## Что в папке
| Файл | Для чего |
|---|---|
| `bot.py` | исходный код нового бота напарника, без изменений; токен передаётся через переменную окружения |
| `add_staff.py` | добавляет ваш Telegram-аккаунт как сотрудника (для проверки панели сотрудника) |
| `queue.sqlite` | локальная тестовая база: создаётся командой `python make_test_data.py`, в GitHub не загружается |
| `images/` | 4 картинки + анимация `bell.gif`, оптимизированные (JPEG, ширина 1280 px, ~130–170 КБ вместо ~2,2 МБ) |
| `requirements.txt` | нужная библиотека |
| `prototype.py`, `schema.sql`, `make_test_data.py`, `backup.py` | файлы Assignment 3 (консольный прототип по-прежнему работает) |

## Шаг 1. Установите Python
1. Скачайте Python 3.10+ с python.org. При установке **поставьте галочку «Add Python to PATH»**.
2. Проверьте в PowerShell: `python --version`

## Шаг 2. Создайте бота и получите токен
1. В Telegram найдите **@BotFather** и нажмите Start.
2. Отправьте `/newbot`, введите название (например, `Dean Queue`), затем имя пользователя, оканчивающееся на `bot` (например, `aitu_dean_queue_bot`).
3. BotFather пришлёт токен вида `1234567890:AAH...`. Скопируйте его. Токен — это пароль к боту, не показывайте его в отчёте и скриншотах и не загружайте в GitHub.

## Шаг 3. Передайте токен безопасно, не меняя `bot.py`
Создайте в папке проекта файл `token.txt`, содержащий только токен от BotFather. Файл включён в `.gitignore` и не должен загружаться в GitHub.

В PowerShell, открытом в корневой папке проекта, выполните:

```powershell
$env:BOT_TOKEN = (Get-Content .\token.txt -Raw).Trim()
```

Эту команду нужно повторять в новом терминале. В коде бота уже есть чтение переменной окружения `BOT_TOKEN`; вставлять токен в `bot.py` **не нужно**.

## Шаг 4. Установите зависимости и создайте тестовую базу
В PowerShell перейдите в папку проекта и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe make_test_data.py
```

**Внимание:** `make_test_data.py` удаляет существующую `queue.sqlite` и создаёт новую базу с выдуманными пользователями. Не используйте эту команду для рабочей базы.

## Шаг 5. Запустите бота

```powershell
.\.venv\Scripts\python.exe bot.py
```

Появится строка `Bot started`. **Окно не закрывайте**: пока оно открыто, бот работает. Остановить — `Ctrl+C`.

## Шаг 6. Сделайте свой аккаунт сотрудником
Тестовые сотрудники в базе имеют выдуманные Telegram ID, поэтому ваш аккаунт для бота — обычный студент.
1. Откройте своего бота в Telegram, нажмите **Start** и отправьте команду `/myid` — бот пришлёт ваш Telegram ID.
2. Остановите бота (`Ctrl+C`) и выполните `python add_staff.py`. Введите ID, имя, роль и PIN (для администратора — `administrator`; для оператора — `operator` и список услуг, например `C R`).
3. Снова запустите `python bot.py`.

Для демонстрации удобно иметь **два аккаунта**: студент (основной телефон) и сотрудник (второй аккаунт или Telegram Desktop). Если аккаунт один, он может быть сотрудником, а студента можно показать вторым устройством.

## Как пользоваться (всё на кнопках)
**Студент**
1. `/start` → приветствие с картинкой и главное меню.
2. **🎫 Взять талон** → при первом разе появится уведомление о персональных данных → **✅ Согласен** → введите ФИО и группу (например, `SE-2619`) → выберите услугу → получите талон (позиция, сколько людей впереди, примерное ожидание).
3. **📋 Мой талон** → текущая позиция, кнопка **🔄 Обновить**.
4. **❌ Отменить талон** → подтверждение. Второй активный талон взять нельзя (правило R8).
5. Когда сотрудник вызывает студента, бот сам присылает сообщение **🔔 «Ваша очередь!»** с картинкой «Студент с уведомлением» (когда впереди остаётся 3 человека, приходит предупреждение ⏰, как в требовании R4).

**Сотрудник**
1. **👨‍💼 Для сотрудников** → введите PIN (бот удалит сообщение с PIN). После 5 неверных попыток вход блокируется на 5 минут. Сессия — 30 минут.
2. Выберите услугу → список очереди → **📣 Вызвать следующего**, **✅ Завершить**, **⏭ Пропустить**, **🔄 Обновить**.
3. Администратор видит ещё **📊 Статистику**. Оператор работает только со своими услугами, чужая услуга → «Доступ запрещён» и запись `denied` в `audit_log`.

## Какая картинка где
| Картинка | Где показывается |
|---|---|
| Жизнерадостная студенческая команда (`team.jpg`) | `/start` и главное меню |
| Очередь студентов (`queue.jpg`) | выбор услуги, талон, панель сотрудника |
| Дружная компания за учёбой (`study.jpg`) | регистрация и помощь |
| Студент с уведомлением (`notify.jpg`) | уведомление «ваша очередь» |

**Анимация.** `images/bell.gif` (480×270, 16 кадров, ~120 КБ) — анимированный колокольчик. Бот присылает его отдельным сообщением сразу после уведомления «🔔 Ваша очередь!». Это декоративный элемент без звука и без подписи: вся информация уже есть в тексте уведомления (для B3: ничего не передаётся только звуком или только картинкой). Telegram сам проигрывает такие анимации в чате без звука. Удалите файл — бот просто не будет её отправлять.

Файлы можно заменить своими с теми же именами (лучше JPEG, ширина до 1280 px).

## Проверка и типичные проблемы
- **Бот молчит.** Проверьте, что окно с `python bot.py` открыто и в этом же терминале установлена переменная окружения `BOT_TOKEN`.
- **`Conflict: terminated by other getUpdates request`.** Бот запущен дважды (например, в другом окне или на другом компьютере). Закройте лишние копии.
- **`Unauthorized` / `InvalidToken`.** Токен скопирован неверно или пересоздан в BotFather.
- **Картинки не показываются.** Папка `images` должна лежать рядом с `bot.py`, имена: `team.jpg`, `notify.jpg`, `queue.jpg`, `study.jpg`.
- **Ошибка про event loop на новом Python.** Обновите библиотеку: `pip install -U python-telegram-bot`.
- **Хочется чистую очередь.** Сначала сделайте копию `queue.sqlite`, затем выполните `python make_test_data.py`: это удалит старую тестовую базу и создаст новую.
- **Тестовые студенты** в базе с выдуманными ID: бот не может им писать, это нормально, он пропускает их без ошибки.
- **Не работает в Казахстане?** Telegram работает без VPN; если нет доступа к `api.telegram.org`, нужна сеть, где он открыт.

## Добавлено для End-term (Project Stage 2)
- **Статистика администратора** теперь показывает самые загруженные часы и среднее ожидание по услугам (ответы на вопросы 1 и 2 из анализа данных).
- **Пропуск студента** в панели оператора помечает вызванный талон как пропущенный; отдельного подтверждения в текущем `bot.py` нет. Студент также может один раз пропустить следующего человека вперёд.
- **После регистрации** бот показывает кнопку «Взять талон» для перехода к выбору услуг.
- **Имитация датчика** `sensor_sim.py`: во втором терминале выполните `python sensor_sim.py`. Скрипт каждые 3 секунды пишет в таблицу `sensor_readings` число людей в коридоре; актуальное значение выводится в меню сотрудника и статистике администратора. Для одного показания: `python sensor_sim.py --once`. Остановка: `Ctrl+C`.

## Совместимость с финальной версией бота и GitHub
- `bot.py` полностью сохранён из отдельного файла напарника, без редактирования.
- `schema.sql` содержит новые поля `pin_rounds`, `near_notified`, `swaps`, `timeout_hinted` и таблицы `pin_lock`, `sensor_readings`; при запуске со старой базой бот добавляет недостающие элементы автоматически.
- `add_staff.py` записывает хеш PIN с 600 000 итераций и значение `pin_rounds`. `prototype.py` умеет проверять PIN как старых, так и новых сотрудников.
- Сам файл базы `queue.sqlite`, папка `backup/` и `token.txt` не входят в ZIP для публикации: базу нужно генерировать локально.
- История коммитов на GitHub должна правдиво показывать, кто написал код, а кто исправил вспомогательные файлы и документацию.
- **Ограничение:** полноценная работа Telegram, включая изображения и уведомления, должна быть проверена с действующим токеном и тестовыми аккаунтами.

## Автоматические тесты без Telegram
После установки `requirements.txt` можно выполнить:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют новую базу, симулятор коридора, добавление сотрудника и лимит талонов на временных тестовых данных. Реальные кнопки, картинки и уведомления Telegram нужно проверить отдельно вручную.
